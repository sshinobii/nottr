# Запуск моніторингу NOTTR

Цей реліз містить збережені гаманці, щоденне сканування та алерти в кабінеті. Telegram запланований окремо.

## Supabase

Якщо жоден із файлів `20261104120000`–`20261104125000` ще не застосовувався, скопіюй вміст `docs/monitoring-migration.sql` у Supabase SQL Editor і запусти один раз. Якщо застосовувався лише деякий файл, запускай решту міграцій окремо в порядку імен. Попередні міграції, включно з `20261104091826_public_scan_limits.sql`, теж потрібні.

Перевір об'єкти після запуску:

```sql
select to_regclass('public.saved_wallets') as saved_wallets,
       to_regclass('public.wallet_observations') as wallet_observations,
       to_regclass('public.wallet_alerts') as wallet_alerts,
       to_regprocedure('public.record_history_page(uuid,jsonb,jsonb)') as history_function,
       to_regprocedure('public.record_approval_signals(uuid,jsonb)') as approval_function;
```

## Vercel

Додай дві нові змінні для Production:

- `PRIVY_APP_SECRET` - секрет застосунку з Privy Dashboard. Потрібен для перевірки холдингу $NOTTR на прив'язаному гаманці.
- `CRON_SECRET` - випадковий секрет не коротше 16 символів. Потрібен для захисту планувальника Vercel.

Залиш існуючі `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `NEXT_PUBLIC_PRIVY_APP_ID`, `ALCHEMY_API_KEY` та інші змінні застосунку. Секрети не повинні мати префікса `NEXT_PUBLIC_`. Після зміни змінних зроби redeploy.

`vercel.json` запускає перевірку щодня о 00:00 UTC. Перевір її статус у Vercel Cron Jobs. За великої кількості адрес або помилок провайдера обробка може затриматися; надалі знадобиться частіший планувальник або черга.

## Перевірка перед анонсом

1. Увійди через пошту і збережи адресу без підключення гаманця. Перевір ліміт у дві адреси.
2. Запусти захищений моніторинг і перевір у профілі час сканування, результат і прогрес історії.
3. Перевір появу тестового сигналу приватності й алерту про необмежений ERC-20 дозвіл.
4. Прив'яжи гаманець із балансом від 1 млн $NOTTR і перевір ліміт у десять адрес.

Прохід історії залежить від даних Blockscout. Перевірка дозволів зараз охоплює лише останні 1000 блоків. Реєстр `risk_indicators` спочатку порожній: автоматичне виявлення відомих скам-контрактів потребує окремого перевіреного джерела для Robinhood Chain.

Для ручного першого запуску після deployment виконай у PowerShell (секрет вводиться у запиті, не вставляй його в команду):

```powershell
$nottrCronSecret = Read-Host 'CRON_SECRET'
try {
  Invoke-RestMethod -Uri 'https://nottr.xyz/api/cron/monitor' -Headers @{ Authorization = "Bearer $nottrCronSecret" }
} finally {
  Remove-Variable nottrCronSecret -ErrorAction SilentlyContinue
}
```

У відповіді `checked` показує кількість оброблених адрес, `failed` - помилки. Після цього онови сторінку кабінету. Якщо production-домен інший, заміни `nottr.xyz` у команді.
